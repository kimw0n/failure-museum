# 실패 박물관 (Failure Museum)

> 이곳의 모든 전시품은 한때 의욕이 있었습니다.

망한 프로젝트·계획·다짐을 "전시품"으로 안치하는 3D 웹 박물관입니다. 장례식장처럼 엄숙한 톤에 한심한 내용만 전시합니다. 공감을 많이 받은 실패는 **불멸의 흑역사관**에 금색 동상으로 모셔집니다.

- 공개 URL: https://kimw0n.github.io/failure-museum/
- 단일 `index.html` (CSS/JS 인라인, 빌드 도구 없음), Three.js 0.170 (jsdelivr importmap)
- 모든 3D 오브젝트는 Box / Capsule / Sphere / Cylinder 조합, 사운드는 WebAudio 합성 (외부 에셋 없음)

## 공간

| 구역 | 내용 |
| --- | --- |
| 입구 로비 | 슬픔 안내데스크, 관장 NPC, 방문객 전광판, 방향 표지판 |
| 메인홀 | 유리 진열장 + 명패. 최신순 배치, 작품이 늘면 줄이 늘어나고 홀이 길어짐. 형광등 깜빡임 |
| 신규 안치실 (왼쪽) | 최신 3점이 관 위에 영정과 함께 안치됨 |
| 불멸의 흑역사관 (오른쪽 계단 위) | 공감 상위 5점이 1~5위 포디움에 넘어진 금색 동상으로 전시. 스포트라이트, 붉은 카펫, 색종이 |

사망 원인별 오브젝트: 귀찮음=이불 덩어리, 마감=부서진 시계, 의욕 증발=1% 배터리와 증발하는 의욕, 팀원 잠수=빈 의자 2개, 알고 보니 이미 있던 서비스=똑같은 상자 두 개, 그냥 잠=Zzz 베개, 기타=물음표 상자.

## 조작

- 데스크톱: 화면 클릭(시점 고정) → WASD 이동, 마우스 둘러보기, Shift 빠르게, 조준 후 클릭/E로 전시품 보기, Esc 커서 해제
- 모바일: 화면 왼쪽 드래그 = 가상 조이스틱, 오른쪽 드래그 = 시야, 전시품 탭 또는 [자세히 보기] 버튼
- 우측 상단: 내 실패 전시하기 / 음소거 / 도움말

## 로컬에서 실행

```bash
python3 -m http.server 8000
```

그다음 http://localhost:8000 을 엽니다. (importmap·폰트 때문에 `file://`로 직접 열기보다 로컬 서버를 권장합니다.)

## 데이터 저장

`index.html` 맨 위의 `CONFIG`로 모드를 고릅니다.

```js
const CONFIG = { SUPABASE_URL: "", SUPABASE_ANON_KEY: "" };
```

- **로컬 모드 (기본값, 둘 다 비움)**: 시드 15점 + 이 브라우저의 `localStorage`. 등록·공감은 본인 브라우저에서만 보입니다. 방문객 번호는 개그용 기본값(4,811)에 이 브라우저의 방문 횟수를 더한 값입니다.
- **공용 모드 (둘 다 채움)**: Supabase REST(fetch)로 모두가 같은 박물관을 봅니다. 25초마다 다른 방문객의 등록/공감을 반영하고 순위가 오르면 속보 토스트가 뜹니다. 요청이 실패하면 자동으로 로컬 모드로 전환됩니다.

### Supabase 관리 방법 (5줄 요약)

1. Supabase에서 새 프로젝트 → **SQL Editor**에 `schema.sql` 전체를 붙여넣고 실행 (테이블·RLS·RPC·시드 15점이 한 번에 생성, 재실행해도 안전).
2. **Project Settings → API**의 Project URL과 anon(또는 publishable) 키를 `index.html`의 `CONFIG`에 넣고 커밋·푸시하면 재배포됩니다 (anon 키는 공개용 키라 노출돼도 됩니다. service_role 키는 절대 넣지 마세요).
3. 부적절한 전시품 삭제: **Table Editor → exhibits**에서 행 삭제 (클라이언트는 RLS 때문에 수정·삭제 불가, 대시보드/서비스 키로만 가능).
4. 공감 수 보정: SQL Editor에서 `update exhibits set empathy = 0 where id = '...';` — 클라이언트는 `increment_empathy` RPC로 +1만 할 수 있습니다.
5. 방문객 수 초기화: `update visit_counter set count = 0;` — 연결이 끊겨도 사이트는 로컬 모드로 계속 동작합니다.

RLS 요약: `exhibits`는 select·insert만 허용(insert는 `title/cause/age/relic/epitaph` 컬럼만, `empathy`·`id`·`created_at`은 기본값 강제), update/delete 정책 없음. 공감 증가는 `security definer` RPC `increment_empathy(exhibit_id)`로만 가능합니다.

### 공감 어뷰징 방지의 한계

과제 수준으로 **브라우저 `localStorage` 기준 작품당 1회**만 막습니다. 따라서

- 시크릿 창, 다른 브라우저/기기, 사이트 데이터 삭제로 다시 누를 수 있고,
- 공용 모드에서는 anon 키로 `increment_empathy` RPC를 직접 호출해 올릴 수도 있습니다.

실서비스라면 로그인(또는 익명 인증) + `(user_id, exhibit_id)` 유니크 테이블, 서버 측 rate limit, IP 해시 같은 장치가 필요합니다. 욕설/광고 필터도 클라이언트의 간단한 금칙어 배열이라 우회가 가능합니다(DB는 글자 수 제한만 강제).

## 확인 체크리스트

배포 후 아래를 직접 확인해 주세요.

### 데스크톱 (Chrome / Safari / Edge)

- [ ] 로딩 화면 "고인의 뜻을 기리는 중..." 후 부고 카드와 "N번째 방문객" 표시
- [ ] "조의를 표하고 입장하기" → 관장 인사 말풍선, 첫 클릭 후 형광등 웅 소리
- [ ] 화면 클릭 시 시점 고정, WASD 이동, 벽·진열장 충돌, Esc로 해제
- [ ] 진열장 조준 시 조준점이 금색 + 하단 안내 → 클릭/E로 상세 패널
- [ ] "나도 이런 적 있음" → 뿅 소리, "ㅠㅠ 나도" 이모지, 카운트 +1, 새로고침 후에도 재공감 불가
- [ ] "명패 이미지로 저장" → PNG 다운로드, 한글 정상
- [ ] "내 실패 전시하기" → 금칙어(예: "카지노") 차단, 등록 시 카메라가 신규 안치실로 이동 + 트롬본 + "삼가 명복을 빕니다"
- [ ] 오른쪽 계단으로 전당 진입 → 팡파레, 색종이, 금색 동상 5개와 명패
- [ ] 공감으로 순위가 바뀌면 상단 빨간 "속보" 토스트
- [ ] 음소거 버튼이 새로고침 후에도 유지

### 모바일 (iOS Safari / Android Chrome)

- [ ] 왼쪽 드래그로 조이스틱 이동, 오른쪽 드래그로 시야 회전 (페이지 스크롤·확대 없음)
- [ ] 전시품 탭 또는 [자세히 보기] 버튼 → 하단 시트 패널
- [ ] 등록 폼 입력 시 화면이 깨지지 않음 (가상 키보드)
- [ ] 전당·메인홀에서 끊김 없이 30fps 이상 체감 (느리면 자동으로 해상도 하향)
- [ ] 무음 모드 해제 상태에서 첫 탭 이후 소리 재생
- [ ] 노치 영역에 버튼이 가려지지 않음
